# 保留内容のライブラリ境界

[English](held-content.md)

`@acp/runtime` は `HeldRequestStore`・`HeldRequestReview`・注入用の
`HeldContentReviewProvider` を公開します。独立した4つのつながり基盤の PR4 です。

ストアは、元の暗号化済み署名付き封筒と所有者が署名したメタデータを
`<dataRoot>/quarantine/<sha256-local-owner-DID>/<id>.json` に保存します。
一覧に入力・タイトル・説明は含めません。既定のプロバイダーは `unavailable` を返し、
内容の保留を継続します。検査ルール・検出器・検査用サブプロセスは含みません。
`hold`・`inspect`・`showReviewedContent`・`discard`・`expire` はライブラリ API です。
内容の表示には、所有者・種類・内容・封筒・レポートのダイジェストに結び付いた
検査完了の受領書が必要です。表示によって実行やつながりの同意を承認することはありません。
タスクのダイジェストは `digest({manifest,input})` を使い、つながりと将来の
アプリケーション用途のダイジェストは復号した本文全体を対象にします。
検査のタイムアウトは既定で5秒です。エラー・タイムアウト・利用不能の場合は保留を継続します。

ホストが所有者の審査を承認し、送信者と所有者の委任関係と期限を検証します。
受信確認は `hold` の成功後にのみ行い、`expire` の実行予定を管理し、
ブロック時には `discardPeer`、判断後にはオファーの削除、結果送信後にはタスクの削除を
呼びます。読み取りはファイルを変更しません。保存期限は指定期限と24時間の早い方です。
上限は100件、封筒1件あたり256 KiB、封筒合計32 MiB、別途メタデータ1件あたり8 KiBです。
期限内のレコードを容量確保のために削除することはありません。
POSIX のパスには0700/0600を使い、Windows は親の DACL を継承し、ACL の検証は行いません。
アダプターの作業ディレクトリが分かる場合は `workspaceDir` を渡し、その配下への保存を拒否します。
タスク検査は組み込みアプリ専用です。ワーカーの受信と保留タスクの審査にタスク検査プロバイダーを
設定してください。単体 CLI はタスク検査もプロバイダーの設定もできず、組み込みの接続審査は
署名付き接続情報だけが対象です。所有者の確認や `--auto-accept` はタスク検査を代替しません。
アプリケーションの通信と UI は今後の対象です。

ライブ経路は[接続の受付](admission.ja.md)に統合しています。既定の検査は利用不可で、内容は保留します。

ゲートウェイは `<data-root>/delivery/<sha256-local-signer-DID>/` に送信待ちの封筒と
受信記録・既定のチェックポイントを保存します。同じ依頼の再到着はアダプターの再実行を
許可しません。検査・所有者による開封は従来の経路で必要です。審査待ちは依頼呼び出しの
終端で、outbox は再依頼しません。再試行は relay の受理または元の期限で止まり、
停止中のゲートウェイは次回起動まで待ちます。[relay の動作](../relay-reliability.ja.md)を参照してください。

### 受信側の配達状態

検証済みの 0.2.0 タスクでは、受信側署名付き `DeliveryStatus` で本文を含まない
保留・開く・アダプターへの引き渡し・終了を記録します。タスク連番・双方向監査とは別です。
未接続の相手には `received_held` と `closed` だけを返し、後の接続承認でも元の履歴を
送りません。検査・表示だけでは開かず、結果成功時の後片付けでは閉じません。
接続解除は待機中の詳細を、ブロックは待機中の全状態を送信対象から外します。
版の宣言がない相手は従来の 0.1.0 の動作です。記録は元の配達期限から7日後まで保持し、
稼働中の保守が期限切れを削除します。引き渡しは既読や実行の証明ではありません。
両ゲートウェイの対応が必要で、relay の配備は不要です。
状態の記録元・保持・動作は [relay の動作](../relay-reliability.ja.md)を参照してください。
