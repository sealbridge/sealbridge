# 0.10.2 release preparation

**CI, root containers, WSL and Claude/Codex development users must review this startup change:** local-executing workers reject effective UID zero before registration or acceptance. Use a dedicated non-root account and its writable data directory, without sudo. Standalone local gateway execution is guarded separately; internal task gateways permit remote OpenAI and board-claim completion. Stdio MCP and local notification commands require the local startup check; remote MCP and URL notifications do not. The official Docker image already specifies `USER node`; requester/admin paths and Windows are unaffected. An operator may explicitly set `SEALBRIDGE_ALLOW_ROOT_LOCAL_EXECUTION=1` in the launch environment only; every overridden startup warns locally. This is never persisted or read from peer/task data, does not approve work, and does not disable root OCI ownership handling or its warning.

Prepare paired `sealbridge` and generated `sealbridge-local` distributions following #330 and #315. The implementation retains the three-way OCI workspace layout, conservative cleanup and local-only diagnostics. This preparation does not authorize merge, tag, publication, a GitHub Release, or deployment.

- All versioned workspace manifests, MCP/A2A metadata and fixtures, installer pins, README public package pins and site expectations use 0.10.2. Generated `sealbridge-local` inherits the root version; sites tooling remains unversioned.
- Preserve 0.10.1-style Windows discovery PATH and fallback, with every OCI CLI cwd and HOME/temp/config variable pointing at unmounted `cli/`. Keep trusted absolute-executable real-Docker test transport separate from normal discovery. Rootless HOME isolation and the observed image-store limitation remain unchanged. Recommend trusted absolute executable paths for receive, notification and wake hooks; their execution/delivery mechanisms remain unchanged, while worker startup consent now includes local command `--notify` under `--allow-local-pc`.
- Internal dependencies stay `workspace:*`; frozen offline installation and lockfile-only regeneration must leave the lockfile unchanged.
- Node >=22, protocol 0.2.0 and `dependencies.ws: ^8.23.0` stay unchanged. Inspect both generated distribution manifests and their nested version metadata after `pnpm run package:cli`.
- The merged maintenance range includes #332, #333, #334, #338, #339, #340 and #341. Main includes #340 at `70924e9`.
- Windows OCI workspaces use LocalAppData and rely on OS profile permissions; no Windows ACL inspection, override setting or startup ancestor screening is included. Recorded identity/no-follow cleanup checks remain. POSIX protections and default subprocess behavior are preserved.
- Verify fixed input removal on terminal outcomes, CLI cleanup only after all owned host clients close, and output removal only after confirmed container release. Unknown CLI runtime storage is retained. Recursive async removal is limited to recorded output after reliable absence and matching identities; POSIX rechecks launcher-owned 0700 parent, Windows relies on OS profile permissions without ACL inspection. Caller deadlines do not cancel issued removal; partial deletion is possible.
- Plaintext temporary files may remain after conservative cleanup. Recommend a dedicated non-root launcher. Never add a startup sweep, follow links or remove unverified legacy paths. Deletion is not secure erasure.
- Record the observed empty/CLI/output remnants after fixed inputs were removed; do not promise input disappearance after hard kill, sharing denial, identity failure or unconfirmed I/O. OCI mount paths containing commas are unsupported by the current argument syntax; use a profile/temp location without commas.
- English/Japanese README privacy sections preserve heading parity. Historical release records remain unchanged. Check the changelog date at publication time.
