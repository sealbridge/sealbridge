# 持ち主が設定する自動受付

[English](auto-accept.md)

すべてのワーカーで同じ設定を使います。新規導入時の既定は「つながっている相手から、読むだけの仕事を自動受付」です。未接続の依頼は、持ち主が対象を変更するまで保留します。公開登録や `--allow-local-pc` は受付の許可ではありません。接続への同意と依頼側の承認も別です。

```sh
sealbridge config auto-accept                        # 表示のみ
sealbridge config auto-accept connected read-only    # 既定
sealbridge config auto-accept invited read-only      # 招待した相手
sealbridge config auto-accept anyone read-only       # 未接続も明示的に許可
sealbridge config auto-accept connected write        # 書き換え・コマンドを明示的に許可
sealbridge config auto-accept off                    # 人による承認
```

設定変更後はワーカーを再起動してください。既存の `<data-root>/config.json` に、他の項目を保持してアトミックに保存します。

```json
{
  "version": 1,
  "relays": ["https://relay.sealbridge.dev"],
  "autoAccept": {
    "version": 1,
    "enabled": true,
    "from": "connected",
    "work": "read-only",
    "limits": {}
  }
}
```

`invited` は、このワーカーの検証済み招待で成立した有効な接続が対象です。現行の最初の所有者への紐付け、期限・失効の規則を維持します。共用招待は追加しません。`connected` は有効な 0.2.0 接続が対象です。`anyone` は未接続でも受け付けますが、接続への同意は作りません。ブロック、明示した相手・依頼者の許可リスト、能力・仕事の範囲・予算・レートの検査はすべて維持します。以前保留した試行は自動で再開せず、新しい依頼を明示的に送る必要があります。

読むだけかどうかは依頼文の自己申告ではなく、ホストが保証する実行特性で判定します。アダプターが `taskAccess: 'read-only'` を保証し、許可されたツールがすべて `readOnly: true` であり、再委譲や実行可能な検証コマンドを含まない場合だけです。API のみの OpenAI 互換アダプターは該当します。任意のコマンド・CLI・MCP・sandbox アダプターは保守的に `write` または人の承認が必要です。組込み側で読むだけを保証するアダプターは宣言できます。この宣言自体は OS サンドボックスや依頼文の解析ではありません。成果物とローカル監査の保存は、持ち主の資源の書き換えには数えません。

ルールに合う依頼は毎回の検査・人の操作なしで実行します。合わない依頼には従来の検査・承認を使います。ワーカー起動時の `--auto-accept`・`--auto-approve`・`--yes` は設定対象を広げず、書き換えをオンにしません。従来の LLM 許可リスト必須条件は廃止します。独自の `PolicyAutoApprovalProvider` や旧 trusted grant も、条件に合わない依頼の自動承認には使えません。書き換え・コマンドを行う組込みアダプターの自動受付には、`autoAccept.work: "write"` の明示が必要です。

署名付き紹介カードにルール全体を載せ、CLI・MCP の依頼者確認画面と招待ページには「この相手は人ではなく自動で応じます」と表示します。依頼側の送信・最終検収の承認は維持します。古いカードはこの項目を持たず、相手の表示設定がローカルの受付権限を変更することもありません。

自動受付の署名付き `ApprovalReceipt.authorization` に `kind: "auto-policy"`、`ruleVersion: 1`、ルール全体の SHA-256 `ruleDigest` を残し、双方向監査の `ACCEPT` に含めます。`--audit` は従来のタスク別保存を使います。未指定時も `<data-root>/workers/<worker-DID-hash>/auto-accept-audit/` に保存し、保存できなければ受け付けません。保持期間・整理は持ち主が管理します。

組込み API の `autoAcceptStateGuard(context, policy)` は今後の上限の検査・予約境界です。件数などの状態をアトミックに読んで予約し、正確に `true` を返した場合だけ自動承認できます。拒否・読取不能・例外なら自動承認に進まず、別の自動承認 provider にも迂回しません。月額上限は下記のとおり実装しています。呼出前サイズ確認は下記のとおりです。#258 の共用招待は未実装です。未知の上限や未対応の版は、黙って制限なしにせず拒否します。#248 の相手別常設承認、公式ワーカーの配備、リレーの変更も含みません。

## 相手 DID ごとの1日の上限

既定は上限なしで、従来の動作を維持します。公式ワーカーの「1人1日3件」は、持ち主が次のように設定します。

```sh
sealbridge config auto-accept max-tasks-per-day-per-did 3
sealbridge config auto-accept max-tasks-per-day-per-did off # 上限を解除
```

ワーカーを再起動してください。受付対象・書き換え許可・有効状態は維持します。
JSON は `autoAccept.limits.maxTasksPerDayPerDid` に正の安全な整数を設定し、省略すると上限なしです。
署名付き AgentCard と監査のルールダイジェストにも上限を含めます。

各ワーカーのローカル ID ごとに、依頼側の**所有者 DID** ごとで自動受付件数を数えます。
同じ所有者のエージェントは枠を共有し、毎日 UTC 0時（日本時間の朝9時）に戻ります。
保存先は `<data-root>/workers/<worker-DID-hash>/auto-accept-daily/<requester-DID-hash>.json` です。
既存 dailyLimit のロック・排他的な一時書き込み・flush・アトミック置換を使い、自動承認の前に枠を確保します。
再起動でも件数を保持し、後続の承認・監査・実行が失敗しても枠は戻しません。
人間が承認した仕事は対象外で、ワーカー全体の `--max-tasks-per-day` は別の上限です。

上限時は `AUTO_ACCEPT_DAILY_LIMIT_REACHED` と、固定の英日メッセージ
「Today's free allowance is exhausted. It resets at 09:00 Japan time (00:00 UTC).」
「今日の無料分は使い切りました。日本時間の朝9時（UTC 0時）に戻ります。」を返します。
状態が読めない・壊れている・ロック中・書けない場合や時計の巻き戻りは
`AUTO_ACCEPT_DAILY_STATE_UNAVAILABLE` で拒否し、その依頼を人間や旧ポリシーの承認へ回しません。
初回のファイル未作成時のみ空の状態を作ります。持ち主は保存ディレクトリを保護・保持してください。
同じタスク ID の再送には `AUTO_ACCEPT_DAILY_TASK_REPLAY` と枠を確保済みである旨の固定英日メッセージを返し、二重に数えません。
永続の `.lock/` ディレクトリに PID と一意な名前のロックを保存し、次の依頼時に OS がプロセスの不存在（`ESRCH`）を確認できた残骸だけを回収します。
生存中・再利用された PID、権限エラー、不正な名前は fail closed です。
ディレクトリは旧版のファイルロック方式を拒否するため残します。状態を共有する全ワーカーは旧版を停止してから更新してください。
所有者を確認できない旧形式の空の `.lock` ファイルは、稼働中のワーカーがないことを確認して運用者が復旧します。生存中のロックやロックディレクトリは削除しないでください。
削除すると件数履歴を失います。DID は自由に作成できるため、複数 DID による利用は防げません。

## 月次のモデル代上限

`sealbridge config auto-accept max-monthly-usd 20` で `limits.maxMonthlyUsd` を設定し、再起動します（`off` で解除）。既定は上限なし、19.99 のような小数 USD も設定できます。**手で承認した仕事も含め、同じローカルワーカー ID の全モデル実行を合算します。** 別 ID・別データルートは別集計です。公式ワーカーは月 $20、相手 DID ごと1日3件、`--adapter openai --model gpt-6-luna` を明示設定します。

料金表は gpt-6-luna だけです。提示された2026-11-11の価格（100万トークンあたり入力 $0.10・出力 $0.50）を、1トークンあたり入力100・出力500ナノドルで整数計算します。サーバー・リレー・運用・割引・キャッシュ料金は含みません。ホスト側アダプターの `billingModel` と `reportUsage` の差分を使い、出力に課金された推論トークンも含めます。未知モデル・別名は承認／実行前に `MONTHLY_MODEL_UNSUPPORTED` と固定文で拒否し、未完了記録は作りません。対応モデルに戻すか持ち主が月次上限を明示解除して再起動すれば、そのエラーで受付が停止したままにはなりません。

キャンセル・時間切れ・予算超過・実行失敗・プロセス落ちなどで使用量が不明な場合は、永続化できた有効なトークン報告を使います。未報告なら**その依頼の manifest に保存した入力・出力の最大トークン数**に料金を掛け、上限いっぱい使ったものとして数えます。ゼロの有効なトークン報告も報告として扱います。署名付き `finish` または `estimate` で一度だけ確定し、使用量不明を理由に永続停止しません。起動・登録・次の受付確認で、落ちたプロセスの開始済み記録を精算します。生存中の別プロセスの依頼は継続し、PID 生存確認の失敗だけでは新規受付を止めません。精算後の遅延報告は二重課金を避けて無視します。承認前の拒否は未使用の枠をゼロで解放します。保存失敗・破損は使用量不明とは別で、履歴を捨てず引き続き fail closed です。

上限後は `MONTHLY_LIMIT_REACHED` で新規受付を止め、実行中は最後まで続けるため超過する場合があります。金額予約は行いません。呼出前サイズ確認は下記のとおりです。トークン報告は報告月、最大予算による推定は精算／復旧した月に数えます。毎月1日 UTC 0時（日本時間朝9時）に戻り、署名付きカードは公開したまま「今月の受付は終了」と表示します。稼働中の公開ワーカーは月替わり後のポーリングで更新します。

拒否文言の既定は通常の固定文「今月の受付上限に達しました。翌月1日 9:00 JST（UTC 0時）に戻ります。」と英語版です。公式ワーカーの持ち主だけ、次を明示設定して「お試し用レビュアー…sealbridge demo / 友だちへの招待…」の固定案内を選びます。

```sh
sealbridge config auto-accept monthly-limit-message trial-reviewer
sealbridge config auto-accept monthly-limit-message standard
```

設定は `limits.monthlyLimitMessage`（既定 `standard`）で、紹介カード・承認ルール digest に含めます。ワーカーはコード、再開時刻、列挙値の文言種類だけを送り、CLI／MCP は検証した時刻と自分の固定文を表示します。相手の自由文は表示せず、未知の文言種類は通常案内に戻します。スキーマの `additionalProperties: false` は維持します。

### 履歴と持ち主向けの復旧手順

集計元は `<data-root>/workers/<worker-DID-hash>/auto-accept-monthly.jsonl` の署名付きハッシュ連鎖履歴です。開始に予算上限を保存し、使用量・完了・最大値による推定を追記して flush します。通常の更新で全体を書き直しません。同じロック内で inode・サイズ・ナノ秒単位の更新時刻／変更時刻が一致する場合だけ検証済み状態を再利用し、外部変更時は署名を再検証します。

月替わりで旧履歴を `.jsonl.<YYYY-MM>.<sha256>.archive` に保存し、稼働ファイルには前月の金額・末尾ハッシュ・未完了依頼を引き継ぐ署名付き checkpoint を置きます。通常の受付で過去月のファイルは読み直しません。アーカイブは持ち主の監査保持方針に従って保存します。`.initialized` は稼働ファイルの消失を検出するマーカーです。初回と月替わりは一時ファイルの排他的作成・アトミック置換、すべての更新は PID claim ロックを使います。ディレクトリ fsync による停電耐性や、持ち主が全状態を消すことへの保護はありません。file-open I/O test limit は450のままです。

プロセス落ちなら通常どおり再起動してください。保存済み報告か予算の最大値で未完了依頼を精算するので、手動クリアは不要です。未知モデルなら gpt-6-luna に設定し直します。BUSY なら共有する全プロセスを停止・不存在を確認し、必要な場合だけ確認不能な古い claim を除去します。集計ファイルを消してロックを直してはいけません。

ファイル消失・破損・途中で切れた書込みが `MONTHLY_STATE_UNAVAILABLE` になる場合：

1. 同じ ID／データルートを共有する全ワーカーを停止し、壊れたファイルとアーカイブを証拠として保全します。権限・保存先・時計の巻戻りを先に直します。一時的なエラーならカウンターのリセットは不要です。
2. 信頼できるバックアップから、完全な所有者署名付き稼働履歴と `.initialized` を復元し、アーカイブも保持します。同じワーカー鍵で検証し、不正な署名や連鎖は受け付けません。最終行の部分書込みは完全な認証済み prefix から復元し、使用量を創作して編集しません。**両ファイルを消してゼロから再開してはいけません。**
3. バックアップ以降に欠けた各依頼を、署名付き manifest とプロバイダー明細から復元します。この版のビルド済み checkout で持ち主のメンテナンススクリプトを使い、`packages/runtime/dist/key-store.js` の `inspectStoredIdentity('worker', identityOptions)` で既存ワーカー鍵を読み、`packages/runtime/dist/index.js` の `workerIntakePath` から正確な集計先を特定します。`packages/runtime/dist/monthly-limit.js` の `MonthlyCostCounter` をその鍵とパスで作り、`counter.reconcileTask(taskId, {maxInputTokens, maxOutputTokens}, {inputTokens, outputTokens})` を呼びます。元の認証済み予算と明細を使い、使用量不明なら第3引数を省略して最大値を計上します。署名付きで追記し、確定済み ID の再実行は二重計上しません。予算未保存だった公開前 v1 の開始済み行にも使えます。`check`・再起動・公開登録は未完了依頼を自動精算するので、その前に行います。秘密鍵を表示したりコマンド引数に貼ったりしません。
4. 精算後のファイルをバックアップし、同じ ID・データルート・モデル・上限で再起動します。完全な認証済み履歴を復元できない場合は停止を維持して保守者に相談し、上限を迂回しません。
## 呼ぶ前の入力サイズ

全ワーカーは、手動承認・自動受付を無効にした場合も、実行前と日次／月次枠の消費前に **400行・48 KiB（UTF-8で49,152バイト）・10ファイル**を検査します。リレーの256 KiBの輸送／検査上限とは別です。所有者の `limits.maxDiffLines`・`maxDiffBytes`・`maxDiffFiles` で個別に上書きでき、正の安全な整数だけを受け付けます。紹介カードの `additionalProperties: false` は維持します。

```sh
sealbridge config auto-accept max-diff-lines 400
sealbridge config auto-accept max-diff-bytes 49152
sealbridge config auto-accept max-diff-files 10
# 1項目を既定値へ戻す（サイズ上限に off はありません）
sealbridge config auto-accept max-diff-lines default
```

変更後はワーカーを再起動します。既存の `--max-input-tokens` と `--max-output-tokens` は引き続き申告予算を制限します。お試しの「中」はそれぞれ30000・4000です。

依頼側のパスは開きません。行数は LF／CRLF／CR を区切りとし、末尾の空行を除き、差分ヘッダーと文脈行も含めます。JSON は全文字列の行数を合計し、バイト数は JSON 全体のシリアライズ後（文字列だけの入力は生の UTF-8）です。ファイル数は `diff --git` ヘッダー数、`+++` ヘッダー数、`files` 配列の要素数、`path`／`file`／`filename`／`filePath` の異なる値の数の最大とし、形式のないテキストは最低1ファイルです。unified diff または明示的なファイル一覧を送ります。リポジトリ解析や添付取得は行いません。

OpenAI 互換アダプター（Anthropic 形式を含む）は、タイトル・説明・JSON エスケープ・出力スキーマを含めた送信メッセージ全体を検査します。UTF-8 バイト数にフレーミング用256トークンを加えた保守的な上界が `budget.maxInputTokens` を超えれば、API を呼ぶ前に拒否します。入力の切り捨てや承認済み予算の引き上げはしません。小さな予算の申告で月次の最大予算による精算をすり抜けることを防ぎます。独自のモデルアダプターも、実際のプロンプトに対応する `validateInput(manifest, input)` を実装してください。

検査に達した試行ごとに、ワーカーのデータ領域の `pre-call-audit/` へ所有者署名付きの `input_size_check` 記録を保存します。タスク／依頼者 ID・時刻・設定上限・結果を記録し、入力本文は保存しません。設定が読めない、数えられない、監査記録を書けない場合は拒否します。サイズ用の可変カウンターは不要です。他の監査証跡と一緒に保存してください。拒否では日次・月次枠を消費しません。

依頼側 CLI／MCP はコードから固定の日英文を組み立て、ワーカーの自由文や余分な項目を表示しません。`INPUT_SIZE_LIMIT_REACHED` は差分の分割、`INPUT_SIZE_UNAVAILABLE` はサイズを確認できない旨を案内します。設定上限が異なる場合も誤表示しないよう数値を固定文に含めません。`MONTHLY_MODEL_UNSUPPORTED` も「現在受け付けられません」という中立文だけを返し、持ち主の設定変更案内は持ち主向けログ／文書に置きます。
